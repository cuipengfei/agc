## 一句话

OMP v18.1.10 有 **82 条内置 slash 命令**：79 条在 core registry（`slash-commands/builtin-registry.ts:38-45`，六类数组合并），外加 bundled 的 `/green`、`/review`（`extensibility/custom-commands/loader.ts:154-171`）和 SDK 注入的 `/autoresearch`（`sdk.ts:2133` + `autoresearch/index.ts:126`）。

## 读表前必知的三件事

1. **「内置」≠ `slashCommandCapability`**。那个 capability 是文件型自定义命令通道（从各 `commands/` 目录加载 `.md`，capability/slash-command.ts:2-4）；内置命令是代码注册的 `SlashCommandSpec`。两者共用补全列表（available-commands.ts:33-99），但来源完全不同。
2. **TUI/ACP 双通道**：spec 有 `handle` 则 ACP 文本模式可用；只有 `handleTui` 则 TUI 专属（builtin-registry.ts:109-114）。下表「ACP」列 = 文本/自动化模式能否用。
3. **运行时对账已做**：82 个名字全部在 dist/cli.js 命中；extension/hook 的 `registerCommand` 是用户侧动态通道，不计入内置。

## 十问补遗（用户追问的源码实证答案）

1. **/restart 谁拉起进程**：进程自己 re-exec（`modes/interactive-mode.ts:4800-5000`）——POSIX 优先 `execReplace`（execvp 族，同 PID 替换镜像），失败或 Windows 退到 `Bun.spawn` 子进程。无父进程守护、无 shell wrapper。
2. **/compact remote 的模型**：可配置，但**没有独立的 compaction model role，也没有任何 settings 级全局压缩模型字段**（settings-schema.ts 的 compaction 段只有 enabled/threshold/methodOrder/remoteEndpoint 等）。唯一解析入口是 `resolveCompactionConfiguredTarget(currentModel)`，只读当前模型的 `compactionModel`（role-models.ts:61-64）；`modelOverrides` 仅按精确 model id 匹配（custom-models.ts:217），无通配符。因此要「所有模型都用同一压缩模型」只能逐模型点名（per-model 定义或 override）。配法：`models.yml` 模型定义里的 `compactionModel`（models-config-schema-bundle.ts:197）或 provider 级 `modelOverrides.<id>.compactionModel`（:249/:309，可覆盖 bundled 模型）；远程压缩另有 `remoteCompaction.model`（:148）。未配置时走候选链 fallback：配置的 compaction 目标 → 当前活跃模型 → 各 role 模型 → 最大窗口模型兜底（session-maintenance.ts:2240-2256）；无 remoteEndpoint 时只保留同 provider 且支持原生压缩的候选（:1350-1355）。
3. **/handoff 产物形态**：手动调用产生两态——内存 markdown document + 提交到当前分支的 compaction entry；**磁盘文件只在 autoTriggered 且 `compaction.handoffSaveToDisk=true` 时才写** `artifacts/handoff/handoff-<ts>.md`（session-handoff.ts:209-228）。handoff 留在当前会话，不新开、不中断现场 agent（session-maintenance.ts:1200-1400）。
4. **/context 的 Autocompact buffer 行显示条件**：纯数值门控，`autoCompactBufferTokens > 0` 才显示（slash-commands/helpers/context-report.ts:37-42）；auto-compact 未启用或无缓冲需求时为 0，行不出现。与版本无关。
5. **/fast 支持范围**：按 provider family（openai/anthropic/google，pi-ai/src/types.ts:192-204）切换；但真正发到线上的只有 OpenAI 直连、OpenRouter 的 OpenAI/Google、Anthropic 直连（realizesPriorityServiceTier，:258-267）。Bedrock/Vertex Claude 与 OpenRouter 的 Anthropic 会被静默丢弃；Fireworks 走独立设置。
6. **/cleanse 与 LSP**：诊断收集不依赖 LSP（checker 子进程 + stdout/stderr parser，checkers.ts:105-138）；但 discovery agent（agent.ts:102-115）与 repair worker（:148）都被授予 `enableLsp: true`，修复阶段可用 LSP 辅助。
7. **/security 扫什么、谁执行**：默认扫当前 Git 仓库（`--path`/`--diff`/`--working-tree` 缩小，security/preflight.ts:13-19）；由专用 security coordinator 会话（沿用当前模型）驱动，再 spawn security-reviewer 子 agent（只读工具 read/grep/glob/lsp/ast_grep）逐文件审。
8. **/collab relay**：默认官方托管 `wss://my.omp.sh`（pi-wire/src/index.ts:422）；可自建，`collab.relayUrl` 配置项（settings-schema.ts:2364-2372），另有 `collab.webUrl`。
9. **/jobs 的 job 类型**：只有 `bash` / `task` / `eval` 三种（async/job-manager.ts:53-54）。
10. **/review 的 reviewer 构成**：主 agent 用 task 工具以 `agent:"reviewer"` 派生的子 agent；模型走 reviewer role 路由，无硬编码。
