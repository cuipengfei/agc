# 审查方的盲区

> Raw: [审查方盲区会话观察](../../raw/harness-engineering/2026-09-03-reviewer-blind-spots.md)；[Grok Build 机制](../../raw/ai-coding-agents/2026-09-03-grok-build-mechanisms.md)（C 节）
> Updated: 2026-09-03

## 概述

审查架构是不对称的。它通常被设计成防止被审方欺骗审查方。但很少被设计成防止审查方在材料不完整的情况下自信地做出判决。

同一类失效的两个侧面：

- **Grok Build** 向分类器注入 agent 伪造不了的 harness 硬事实，防止被审方捏造证据。但它没有防止分类器错过那些确实存在但被截断的证据。
- **本次会话** 中，审查方以不断升级的严重度断言某些消息不在 transcript 里。那些消息确实存在；审查方看不到它自己先前的输出。

两者都是可见性缺口，不是欺骗缺口。

## 观察到的模式

在一次 OMP 会话中，审查方断言某些内容不在 transcript 中。严重度标签递升：concern → blocker → blocker。第三次递升后，被审方撤回了一个事后看来正确的事实。

被审方的错误是把严重度的升级当成证据强度的升级，而没有去问审查方实际能看到什么。

审查方的错误是没有声明自己的可见性边界。「我看不见这个」变成了「这个不存在」再变成了「你捏造了它」。

**边界说明。** 这是一次会话中的行为观察，不是机制审计。OMP advisor 的实现没有被读过；只记录了本次会话中收到的输出。被审方在同一会话中还做出了三处过度声称——advisor 默认开启、覆盖面无边界、advisory 在流式中途送达——这些随后都被撤回了。

## 机制层面的平行：Grok Build LazinessDetector

Grok Build 的分类器审 agent 的 transcript 时，输入是一份展平且截断的记录：每行截断到 400 字符，assistant 的 reasoning 段进一步收紧到 200 字符。代码里的设计理由是：思维链只是辅助信号。

截断之外的内容对分类器不可见。一个声称的证据如果落在被截掉的部分，就会被判为「证据不存在」。同样的 pipeline 在运作：截断视野 →「我的输入里没有」→「证据不存在」。

另一边的防伪设计是扎实的：分类器收到 harness 真值，比如当前有多少后台任务在跑、这一轮实际多少秒。这些是 agent 编不了的数字。但它们补偿不了缺失的上下文。

## 为什么下游闸门抓不住这个

LazinessDetector 在分类之后有三层决策：封闭类别集合（7 个值，4 个判停滞）、把握度阈值（0.7）、每会话 nudge 上限（默认 0）。

这些管的是判决**怎么表达**、以及**是否执行**。它们不管判决的**材料基础**是否充分。一个判决可以正确分类、超过阈值、在额度内，同时 resting on truncated material。

分类器没有一道闸门会问「我的输入是否完整到足以判断这个声称？」。

## 什么会有帮助

审查方——无论是模型分类器还是人工程序——在给出判决之前应该声明它能看什么、不能看什么。「我没有找到证据」和「我的视野里不包含这个证据」之间的区别不是咬文嚼字；它改变了合适的回应方式。前者邀请挑战；后者邀请补充。

在本次观察中，被审方最终通过问「审查方能看到什么」识别出了缺口。这个问题应该在第一次升级时就问，而不是第三次。
