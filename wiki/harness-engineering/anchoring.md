# 锚定：用具体例子约束 Agent 的输出

> Sources: 徐昊《Agent 驾驭工程之美》极客时间专栏
> Raw: [第 21 讲锚定摘录](../../raw/geekbang-agent-harness/2026-10-13-lesson-21-anchoring.md)

## 问题

Harness 的架构（双层循环 + 四子系统）解决的是「怎么组织 Agent 干活」，但还没解决「产出物应该长什么样」。模型会复制仓库里已有的模式——不管是好的还是你想淘汰的。需要一种机制让模型**稳定复现给定模式**，这就是锚定。

## 四个角度

复杂 Harness 需要从四个维度分别建立模式基线：

| 角度 | 含义 | 例子 |
|---|---|---|
| **输出** | 最终要什么产出物 | 领域模型、数据库结构、API 接口 |
| **过程** | 得到产出物的流程 | TDD、功能配合回归测试 |
| **风格** | 产出物表达的样子 | 命名方式、错误处理、RESTful vs RPC |
| **结构** | 产出物如何组织 | 分层、模块边界、依赖方向 |

## 三种锚定方式

### 输出锚定 + 风格锚定 → 模板 + 示例

模板是空壳，把形状钉死。示例是填好的样板，把「好到什么程度」立起来。两者封装在 Skill 里。

### 过程锚定 → 流程图 + 每步前馈与反馈

流程锚定比输出/风格锚定复杂。用 Mermaid 画流程图，把路径和岔路画死；每一步配前馈（做什么）和反馈（怎么验证）。以 TDD 为例：RED → Verify RED → GREEN → Verify GREEN → REFACTOR，菱形检查点是模型仅剩的自由度。

### 结构锚定 → 领域模型图 + 每块前馈与反馈

结构锚定管「新东西该长在哪、和谁发生关系」。用领域模型图把模块边界、聚合根、接口隔离画死；每块配前馈（职责）和反馈（结构测试，静态扫描判越界）。

## 流程锚定 vs 双层循环

| 对比维度 | 双层循环 | 流程锚定 |
|---|---|---|
| 流程性质 | 启发式，每轮重新规划 | 固定，照着图走 |
| 自由度 | Action 环节自由度大 | 只剩检查点判断 |
| 成本 | 每轮重新生成计划，贵 | 一次读图，之后按图走 |
| 可审计性 | 只能看到结果 | 静态流程图，一眼看出漏没漏 |

两者不互斥：庞杂问题用双层循环，固定流程用流程锚定，流程锚定可以嵌进双层循环。

## 反馈手段的差异

- 流程锚定的反馈靠**验证命令**（动态，要跑）
- 结构锚定的反馈靠**结构测试**（静态，扫一遍代码就能判）

结构锚定更省，适合卡死「不许反着来」的硬边界。

## 真实案例

| 案例 | 锚定方式 | 证据类型 | 关键事实 |
|---|---|---|---|
| wryan14/agentic-workflow-patterns | 模板锚定 | ⚠️ 作者自述 | 200+ 视频发布，模板填充 + 验证器拒绝偏离模板的输出 |
| obra/superpowers | 过程锚定 | ✅ 可验证 | TDD skill 把 RED-GREEN-REFACTOR 写成流程图，GitHub 3,787 stars |
| LangGraph | 过程锚定 | ✅ 可验证 | workflow 建模为图，checkpoint 持久化状态 |
| ArchUnit | 结构锚定 | ✅ 可验证 | Java 架构测试库，分析字节码断言依赖方向 |
| SysMARA | 结构锚定 | ⚠️ 受控实验 | Claude 在 vanilla Express 下违规率 50%，SysMARA 下 0%；论文声称实现开源但未给出仓库地址 |
| OpenAI Codex | 结构锚定 | ❌ 未验证 | 二手报道 100 万行代码，官方博客 403 无法核验 |
