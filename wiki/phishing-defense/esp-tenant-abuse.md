# ESP 租户滥用：认证通过不等于内容可信

## Overview

SPF、DKIM、DMARC 全部通过，说明邮件使用了某个域名的授权发信身份；它不能说明发信人的意图。一个常见的滥用路径是拿到该域名在 ESP（邮件服务商）的租户访问权，用租户的 DKIM 私钥与 SPF 授权 IP 发信。收件方看到的是合法域名与完整认证，内容却可以是任意钓鱼文案。

## 认证链：域名、DNS 与 ESP 的分工

- 域名所有者在 DNS 中发布 DKIM 公钥（selector 由域名与 ESP 约定），私钥交给 ESP 保存，或由域名所有者上传给 ESP。
- SPF 记录把 ESP 的发信 IP 列为授权来源；退信地址通常使用 ESP 管理的子域，例如 `nc.<abused-domain>`。
- DMARC 策略可以设为 `p=REJECT`，但只要 From 域与通过的 DKIM 签名域一致，认证就会通过。
- ESP 租户是这条链上的执行者：谁拿到租户访问权，谁就能用该域名的签名能力发信。

## 头部怎么读

- `Return-Path` 显示退信地址，通常是 ESP 的退信子域；它可以与 From 不同。
- `Authentication-Results` 给出 SPF、DKIM、DMARC 的结果；要同时看 `header.i=`、`header.d=` 与 From 域是否一致。
- `DKIM-Signature` 的 `d=` 是签名域，`s=` 是 selector。签名域与 From 域一致时，DMARC 的域匹配检查通过。
- `From` 的显示名是自由文本，可以写成任何品牌；真正被认证的是尖括号里的地址域。
- `Reply-To` 不参与认证，可以指向任意域。

## 为什么 DMARC 放行

DMARC 检查 From 域与通过认证的域是否属于同一授权身份。在这类攻击里，发信使用的正是该域名的 ESP 租户，DKIM 签名域与 From 域一致，SPF 也由同一组织域的退信子域通过，所以 DMARC 按规则放行。DMARC 拦不住授权账户被滥用的情形。

## 账户接管的常见入口

- ESP 账户密码被钓鱼或撞库，账户没有开启两步验证。
- API Key 或 SMTP 密码泄露，来源可能是代码仓库、恶意软件或第三方工具。
- 代运营公司或代理商的账户被攻破，它同时持有多个客户域名的发信权限。
- 内部或外包人员滥用权限。

邮件头能证明使用了授权租户，无法区分具体入口；需要 ESP 与域名所有者查账户日志、活动记录与登录历史。

## 检测与处置

- 收到认证全部通过、内容却与发信组织无关的邮件时，不要用“认证通过”当作内容可信的依据；先看发信域与邮件内容的业务关系。
- 把邮件的消息标识、活动编号与收信时间交给 ESP 的滥用通道和域名所有者的安全联系人，平台可以定位租户与群发任务。
- 域名所有者侧：ESP 账户开启两步验证、使用最小权限的 API Key、监控异常群发、定期审计代运营账户。
- 收件方侧：标记钓鱼；对同一发信域的其他邮件保持警惕。

## 证据边界

- 本页的认证结论来自一封脱敏邮件的头部观测：SPF、DKIM、DMARC 均为 PASS，DMARC 策略为 `p=REJECT`。
- 具体入侵入口无法从邮件头判定；账户接管、密钥泄露、代理商被攻破与内部人员滥用都能产生同样的头部。
- 邮件正文的零宽字符可能来自正规模板或复制过程，不能单独作为伪造判据。
