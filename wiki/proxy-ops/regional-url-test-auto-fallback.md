# 地区自动选线与测速判定：url-test 组的实测行为

> Sources: 本机实测与 mihomo v1.19.33 源码核对, 2026-11-19
> Raw: [地区自动选线与测速判定实测](../../raw/proxy-ops/2026-11-19-regional-url-test-auto-fallback.md)
> Updated: 2026-11-19

## Overview

让同一地区的多个机场节点自动切换，做法是新增 `url-test` 组：`include-all-proxies: true` 加 `filter`（正则匹配节点名）圈定候选，订阅更新后节点增减自动跟随。组按 `interval` 周期对每个候选发一次 HEAD 请求记延迟，选点取最近一次延迟最低者；节点失效有两条被发现的路：定时测速判失效（最多等一个周期），或实际建连失败 3 次（5 秒窗口内）立即触发整组补测。切换只影响新建连接。测速判定的是"该节点到测速地址的可达与延迟"，换测速地址会改变候选集，本机 17 个香港节点双地址实测给出量化对照。

## url-test 组的配置面

本机（Clash Verge Rev 2.5.10 + mihomo v1.19.33）落地两个地区组：

| 字段 | 值 | 作用 |
|---|---|---|
| `type` | `url-test` | 自动选线组 |
| `include-all-proxies` | `true` | 引入订阅全部节点 |
| `filter` | `香港` / `美国` | 按节点名正则圈定候选 |
| `url` | `https://github.com/`（香港）；`https://daily-cloudcode-pa.googleapis.com/`（美国） | 测速与健康判定地址 |
| `interval` | `180` | 测速周期秒数，加载时先测一轮 |
| `timeout` | `5000` | 单次测速超时毫秒 |
| `tolerance` | `0` | 候选快过当前值超过该毫秒数才换 |
| `max-failed-times` | `3` | 组内建连失败累计触发补测的次数 |
| `lazy` | `false` | 空闲时也不暂停测速 |

候选数量按节点名匹配：本机香港 17 个、美国 6 个。TUN 与选线无关，组行为在 TUN 与系统代理下一致。

## 选点与切换

选点取每个候选**最近一次**测速延迟，有历史但最后一条失败的按最大延迟处理，等于排除。选点结果缓存约 10 秒，期间新连接复用同一节点；定时测速周期内不清此缓存。`tolerance: 0` 意味着只要别的可用候选更快就换；设大容差可减少两个延迟接近的节点间来回跳。

节点失效有两条独立的被发现路径：

1. **定时测速**：到组 `url` 的 TCP 连不上、TLS 握手失败、`timeout` 内拿不到响应，任一发生即标记失效，下一轮选点跳过。最坏要等一个 `interval`（本机 180 秒）才反映到选点。
2. **实际建连失败**：通过该组新建连接连续失败累计到 `max-failed-times`（3 次，且都在 5 秒窗口内），或收到 connection refused，立即触发整组健康检查并重新选点。建连成功会重置计数。这条是实际故障时的主力。

两条都只统计"建立连接"阶段。已建立的连接不迁移、不断开；换节点只影响之后的新连接。节点能连上但下载慢不会判失效，只会在下一轮因延迟数字落后不再被选；延迟与带宽无关。全部候选都失败时，URLTest 退回用组内第一个成员尝试，连接可能失败。

手动在 GUI 点 URLTest 组内的具体节点会形成固定（fixed）：固定节点存活时优先用它，失效后自动回退到延迟最低的可用节点。点组内延迟测试按钮解除固定。

## 测速地址决定候选集

测速判定的是"该节点到该地址的可达与延迟"，不是"节点整体好坏"。2026-11-19 本机 17 个香港节点双地址实测（各测一次，5 秒超时）：

- 两个地址都通：9 个。
- GitHub 失败、gstatic 通：2 个（`香港01|广港专线`、`香港07|广港专线|家宽`，后者 gstatic 184 毫秒，线路本身很快）。
- 两个地址都失败：6 个，此刻节点本身不可用，与地址无关。

具体数字见 raw。含义：测速地址是被敲的门，不是线路本身；换地址会改变候选集。失败原因（GitHub 拒绝该出口 IP、节点到 GitHub 的路由差、当时不稳定）无法从测速结果分辨。gstatic 也不对每个节点都更优（`香港02-海外中转` GitHub 192 毫秒、gstatic 507 毫秒）。选测速地址的依据应该是"这个地址能不能代表我实际要用的服务"：日常要用 GitHub，用 GitHub 测速使被其拒的节点出局就是对的。

## Clash Verge Rev 的接入与显示

扩展脚本（`profiles/<script-uid>.js`）新增组、把组名 push 进主 select 组的 `proxies` 列表，不改任何现有组定义与名字；规则增强文件把七个域名的规则目标改为美国自动组。加载后 GUI 行为（v2.5.10）：

- 前台约 15 秒向 controller 拉一次代理视图，组头与选中节点随之刷新；后台暂停拉取。
- URLTest 组被固定的成员显示📌，悬停文案为"进行延迟测试，以取消固定"。
- 无需手点测速按钮：组加载即测，之后按 `interval` 周期自动测；手点是额外立即测一轮。
- 主 select 组选香港自动后，默认流量与引用主组的服务组跟随；选择持久保存，订阅更新后保留。

规则第三项从节点名换成 url-test 组名后，节点失效不再需要改规则，组内自动换；组名是稳定名称，也避开订阅更新改节点名导致的加载失败。

## 证据边界

双地址实测每节点每地址只测一次，是当时快照，节点状态会变；失败原因未做进一步定位。热加载经 `PUT /configs` 核对生效，Clash Verge 后续自行重新生成配置的路径未验证。选点、容忍度、固定、补测的行为来自 v1.19.33 源码直读，非文档转述。
