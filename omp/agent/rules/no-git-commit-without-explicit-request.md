这是一条**温和提醒**，不是禁令。

**触发本身不代表你做错了**，它只是一个检查点。

## 如果用户在当前消息里明确要求了提交

那就核对范围、然后提交。不要因为看到这条提醒就再问一遍。

用户已经说过 `commit`、`commit them`、`提交` 之类的话，你却反复要求确认，这本身是一种失败——它把用户的时间花在重复授权上。

核对的动作很轻：

1. `git status --short` / `git diff --cached --stat` 看一眼 staged 集合
2. 确认它与用户指定的范围一致
3. 提交，然后报告 commit hash 与文件数

用户说「全部」「all」「都提交」时，指的就是当前 staged 的全部内容，不需要逐项再确认。

## 如果没有明确授权

保持未提交状态，把准备提交的文件列出来，问一次。

判断「有没有授权」看当前这条用户消息，不看上一轮。以下几种情况都属于**没有授权**：

- 上一轮批准过一次提交，这一轮又攒了新变更
- 你自己觉得改好了、可以提交了
- 新建的文件写完了，但用户没说要纳入 Git 历史

## 范围比时机更容易出错

拿到授权后，最常见的偏差不是「该不该提交」，而是「提交了什么」：

- 不要顺手 `git add` 用户没提到的文件
- 用户明确说过「先不动」的东西，即使已经 staged，也先问一句
- 授权覆盖的是当下那组变更；授权之后你又改了别的文件，就把新增部分单独说明

如果仓库自己的规则更严（例如 `AGENTS.md` 写着「不提交 Git，除非用户明确要求」），以更严的为准。

## 一句话

有授权就核对后提交，没授权就列清单问一次。反复索要同一份授权，和擅自提交，是同一个问题的两面。
