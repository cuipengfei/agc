# Gemini 4 Argon 缓存归属：账号绑定与 x-interaction-id 单变量对照

> Source: 本机对 8787 → 4140 网关的 Gemini 4 Argon 直连实测与会话记录
> Collected: 2026-11-28
> Published: Unknown

## 一、五端口轮换与复访

本机 4142 至 4146 五个 Copilot API 实例各绑定一个不同的 GitHub 账号。以相同正文依次请求 4142 → 4146，五次请求的 `cached_tokens` 全部为 0。随后回头复访各实例，每个实例都读到了自己那份缓存：4146 命中 3,181 tokens，4142 命中 2,833 tokens。

复访时的缓存量均比各自首轮输入少 2,049 tokens。计费分项里 `cache_read` 单价为 `input` 的 1/20，`cache_write` 单价为 0，本次记录的写入 token 数也为 0。

## 二、同账号更换凭据与会话标识

同账号条件下更换 Copilot token、更换 `vscode-sessionid` 后，重复请求仍命中 3,268 tokens。保持其他条件不变而切换账号，命中归零。

结论：缓存跟着 GitHub 账号走；换进程、换会话标识、换 token 都不改变归属。

## 三、x-interaction-id 固定与轮换对照

对 `gemini-4-argon` 做 5 组配对，共 60 次真实请求。每组的两个实验臂各先发 seed 与 baseline 两次请求确认缓存已建立，再做 4 轮追加对话，两条臂的轮次顺序交错执行，避免时间偏置。一个臂全程固定同一个 `x-interaction-id`，另一个臂每轮换新 ID。

结果：固定臂 20 次追加请求中 1 次严重掉点、其中 1 次归零；轮换臂同样 20 次追加请求中 1 次严重掉点、其中 1 次归零。两臂正常命中时的缓存读取区间都是 0–17,341 tokens，命中占输入比例都在 0.8931 至 0.8934 之间。

未观察到固定 `x-interaction-id` 的优势，也不能据此排除其他模型、其他账号或其他负载条件下存在差异。

## 四、一处撤回的说法

早先根据跨账号相同正文出现命中，推断过「跨账号共享同一份缓存」。后续复核表明该现象与换账号归零的实验结果相互矛盾，且缺少受控条件，该说法撤回。可复现的事实是：换账号归零，同账号更换 token 与会话标识仍命中。
