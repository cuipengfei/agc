# 徐昊《Agent 驾驭工程之美》坏味道系列——用户问题概念摘录

> Source: 极客时间专栏 https://time.geekbang.org/column/intro/1428
> Collected: 2026-10-02
> Published: 2026-09

## 需求模糊 → 怎么让 Agent 不猜？（07，article/1012101）

约束条件、完成条件、边界情况三个内容合在一起，就是把一句话的需求，变成了一个 Agent 不需要猜就能执行的指令文件。

约束条件写得越具体，Agent 需要猜测的空间就越小。

完成条件必须是可验证的，不能是主观判断。当你把完成条件从"感觉差不多了"变为"数据达标了"，Agent 就知道自己做完后该检查什么。

边界情况不写，Agent 就不会处理。

诊断信号按严重程度递增：Agent 反问"这里我应该怎么做？"→ 交付的东西"看起来对，用起来不对"→ 验收时反复说"我不是这个意思"（此时伴随优先级丧失：对话中的每句话对 Agent 权重一样，它分不清核心约束和随口一说）。

## 虚假胜利 → 怎么防止 Agent 跳过难的宣布完成？（10，article/1014410）

惰性生成是指大模型过早终止任务，系统性回避需要更多推理的复杂部分，只处理容易的部分，然后对整个任务自信宣布完成。

三个特征：容易的做且做得快、复杂的跳过但不告诉你、对整个任务宣布完成。

终止条件失效的两个原因：过度自信（Agent 系统性给出正面评价）、认知统一（生成和评估是同一个 Agent，盲点原样保留）。

消除手法：分离执行与验证。生成者只负责产出，验证者独立判断是否完成。验证者可以是脚本：判断逻辑写成代码就是可重复执行的验收测试。

## 指令腐化 → 为什么规则越加 Agent 越笨？（11，article/1015204）

指令文件腐化的本质是"只增不减"：每一条规则加进去时都解决了当下的问题，但规则累积之后，优先级冲突、矛盾累积和模型自身的注意力局限会让 Agent 的行为越来越难以捉摸。

治理的核心是三件事：优先级确定、矛盾检测以及定期清理。

优先级是整个维护机制的基础：矛盾检测时靠它裁决哪条胜出，定期清理时靠它决定先删哪条。

矛盾本身不可怕，可怕的是矛盾一直隐藏着，让 Agent 每次随机选一条。显式的矛盾可以处理，隐式的矛盾只能靠运气。

## 前馈痴迷 → 为什么写了规则还是出错？（12，article/1016080）

前馈和反馈本质上是概率和证据的区别。前馈提高的是"做对的概率"，反馈提供的是"做对的证据"。

造成这个坏味道的是同一个习惯：不愿意面对"描述做完的结果"这个更难的认知任务。于是我们看到一个普遍的现象：指令文件越来越厚，反馈环节却总是相对薄弱。

消除手法：反馈优先。当你觉得需要给 Agent 加一条控制时，先写它的结果检查形式，而不是过程规则形式。

## 上下文倾倒 → 信息给多了为什么反而差？（14，article/1017556）

上下文预算（Context Budgeting）：把上下文看作珍贵的资源，窗口是有限的，注意力是有限的，每一段信息都要花钱。

四种方法各有分工：筛选决定"给不给"，分层决定"怎么组织"，按需加载决定"什么时候给"，压缩决定"以什么形式给"。

作者的实操顺序：按需加载 → 压缩 → 分层 → 筛选。

## 上下文焦虑 → 接近窗口上限时为什么行为退化？（15，article/1018504）

上下文焦虑指的是，Agent 在接近上下文限制时表现出的行为退化：匆忙完成、跳过验证步骤、选择简单方案而不是最优方案。

与惰性生成的区分：惰性生成是随时可能发生（没有外部验证就跳过难的），上下文焦虑只在资源压力下触发（上下文充足时表现正常）。

治理手段：双层循环 + checkpoint + 上下文预算 + subagent。

## 跨会话知识丢失 → 新知识为什么没有渠道？（16，article/1019406）

跨会话知识丢失指的是，在多会话的场景下，执行中发现的新知识（discovery）、用户通过对话产生的判断（user triage）和决策（decision），没有同步到其他会话当中，当前会话结束之后，这些知识就丢失了。

新知识分三类：用户统筹（依赖用户输入，优先级与偏好的表达）、发现（模型执行中自己发现的）、决策（模型自主或用户裁决）。

操作分两层：内层循环收尾时清点本轮产生的知识，外层循环做归位（决策放 ADR、领域知识放 wiki、偏好归入对应文件）。

## retro skill 是否实现动态知识更新？（本会话查证）

> Source: ~/.agents/skills/retro/SKILL.md

retro skill 定义为提出 coding-agent 环境改进建议，按严重程度向用户展示候选项。它不对应课程的动态知识更新——它是环境改进（导航指针/自动化检查/编码标准），不是知识归位到 ADR/wiki/偏好文件。
