## 四角度定义

针对大模型和构建 Harness，从四个角度去考虑问题域：输出、过程、风格、结构。

- 输出，是最终需要什么样的产出物
- 过程，是为了得到相应的产出物必需的流程
- 风格，是产出物表达的样子
- 结构，是产出物如何组织

以软件开发的 Harness 为例。构建一个后台 API 系统，需要的输出是领域模型、对应的数据库结构、业务逻辑以及 API 接口。得到这些输出的流程，可能是测试驱动开发，也可能是功能配合回归测试。风格则是命名、错误处理方式以及 API 接口风格（/orders/{id} RESTful 风格而不是 getOrderById 这样 RPC 的形式）。结构就是代码的分层与模块边界，还有每一层的职责划分。

## 锚定的定义

需要大模型能够稳定地复现给定的模式。也就是针对输出、过程、风格、结构，能够稳定地以给定的模式为参考，完成我们需要的功能。前面讲过坏味道模式复制漂移，以及它的对应重构手法模式基线化（Pattern Baseline）。

在构造复杂 Harness 的时候，通常需要分别为输出、过程、风格、结构建立对应的模式基线，也就是我们所谓的锚定（Anchor），从而依靠锚定规范 Harness 的行为。针对输出、过程、风格、结构四个不同的方面，锚定的方式也不尽相同。

## 构造锚定：模板 + 示例

构造锚定最简单的方法是模板（template）和示例（example）。通常我们可以把模板与示例封装在技能（Skill）当中。

模板是约束大模型输出最简单的方式，比如规范代码评审的输出内容：

```
位置    <文件>:<行号>
级别    blocker / major / minor
类型    正确性 / 可读性 / 性能 / 安全
问题    一句话说清哪里不对
建议    怎么改，能贴代码就贴
```

示例可以用于建立更复杂的基线。比如构造 UI 功能测试时，需要使用 Page Object 对象，与测试代码配合。

## 流程锚定

对于输出锚定和风格锚定，通过模版和样例通常就足够了。但是对于过程锚定则要复杂一些。

两种做法：

1. 继续使用双层循环结构。弊端在于，双层循环依赖 PDCA 以及子任务分解，它主要解决的问题是如何启发式地解决一个庞杂问题，而不是精准地依照某个特定流程执行。虽然也能对流程起到约束的作用，但如果仅仅是想遵循某个固定的流程的话，那么双层循环还是稍显复杂。

2. 流程锚定：使用 Mermaid 画出明确的流程图，然后再为每一步提供前馈与反馈。比如把测试驱动的流程写成流程图，再对每一步进行描述。

### 流程锚定 vs 双层循环的四点对比

第一，双层循环是启发式流程，每轮都在想下一步做什么，流程锚定要的是照着图走。双层循环靠 PDCA 和子任务分解，每一轮都是一次新的规划。对一个没有标准解法的庞杂问题，这是对的，因为路径本身要边做边探。但对 TDD 这种路径早就画好的流程，还让它每轮重新规划，就是拿一台做启发式搜索的机器去背一篇写好的流程，既贵又不准。

第二，流程锚定把自由度收得只剩「在检查点做判断」。流程图里的菱形，就是模型仅剩的自由度：验证失败原因对不对、验证全绿没？其余地方没有发挥空间。双层循环里，内层循环的 Action 环节自由度大得多，模型自己决定下一步做什么，换来的是灵活，代价是不确定。

第三，成本差得远。双层循环每轮都要把计划、分解、下一步重新生成一遍，词元（token）和时间都花在反复规划上。流程锚定的路径是死的，模型花一次读图的开销，之后就是按图走，每步只剩执行加那一个判断。

第四，可审计。流程图是静态的，你能一眼看出流程漏没漏、判断点全不全、哪一步没配反馈。双层循环的动态规划过程，你只能看到结果，看不到它当初为什么那么走。

对于小范围有明确定义的流程，使用流程锚定是更简洁的做法。流程锚定和双层循环并不是互相排斥的，流程锚定可以嵌进双层循环，外层循环的某个环节，本身也可以是一张画好的固定流程。

## 结构锚定

结构锚定锚的是分层、模块边界、依赖方向。流程锚定管的是「怎么一步步走」，结构锚定管的是「新东西该长在哪、和谁发生关系」。和流程锚定一样，光靠一句「业务逻辑放 service、controller 只做校验」不够，模型能复述，写出来还是乱放。所以也要用画图的办法，用领域模型（domain model）或者系统分层图，把边界和依赖方向画死，再为每一块配上前馈与反馈。

结构复杂的时候，图就要跟着复杂。画一张领域模型图，把模块边界、聚合根、接口隔离一起画出来。

和流程锚定同构，图管「形状」（边界和方向），每块的前馈管职责，反馈管越界没有。差别在反馈的手段：流程锚定的反馈靠验证命令，是动态的、要跑；结构锚定的反馈靠结构测试，是静态的、扫一遍代码就能判断。所以结构锚定比流程锚定更省，也更适合卡死「不许反着来」这类硬边界。

## 小结

针对大规模 Harness，输出和风格靠模板（template）加示例（example）把形状钉死，流程靠流程图加每一步的前馈与反馈把路径钉死，结构靠领域模型图加每一块的前馈与反馈把边界钉死。把这三种方式用到四个角度上，就把「长什么样、怎么走、落在哪」都钉住了，模型才能照着这些基线稳定地复现给定的模式。
