- Regular：`20564520` bytes，SHA-256 `a575f533481139875243926514a5883dda4f5d24d6bf8c57586d6e146f0dfeec`
- Bold：`20517832` bytes，SHA-256 `1f6369330d1e00daa05981ab4832dae9d9c1897553e0e0112964b44d1f572acd`

## 时间分支静态数量

`panics` 总数 `33`；按消息 `time not implemented on this platform` 筛选后：函数 `32208`（18 处调用）与 `32209`（3 处调用），合计 21 处。「调用数」是 `callers` 数组长度，指直接调用该 panic 函数的函数个数。本版本未应用时间补丁。

## 部署过程与 site 目录核对

装配时第一次运行因目标目录 `/home/cpf/.local/share/tern-web-0.9.10` 已存在而先删除再重建。删除前核对：该目录当时含 `fonts.json`、两份字体与空的 `verification/`；0.9.8（`tern-web-0.9.8-fixed/verification/`）与 0.9.9（`tern-web-0.9.9/verification/`）的同类目录同为空。重建后逐项与 `deploy-manifest.json` 及原版 hash 对照，未发现内容损失。相邻版本 0.9.6、0.9.7 的验收记录完整，不在删除范围内。

后续流程约定：删除或重建 site 目录前，先与 `deploy-manifest.json` 逐文件核对 hash，`verification/` 非空时先把记录移出，再决定复用或重建。

## 正式部署状态

服务以手工命令启动，重启后沿用 `~/.config/tern/web-token`。本机 `$XDG_RUNTIME_DIR` 为 `/run/user/1000`（UID 1000），以下命令按本机实测路径记录；其他机器以各自的 `$XDG_RUNTIME_DIR` 为准：

```bash
tern daemon --socket /run/user/1000/tern/daemon.sock &
tern web serve --listen 127.0.0.1:8378 --token ~/.config/tern/web-token --assets ~/.local/share/tern-web-0.9.10 &
```

实测：`tern --version` 返回 `tern 0.9.10 (2ad447b)`；HTTP 200；pane ID 为 `[326417514503, 326417514501, 347892350977, 536870912003]`，与 0.9.7–0.9.9 历次切换保留的集合一致。部署记录写入 `~/.local/share/tern-web-0.9.10/PATCH.md`。
