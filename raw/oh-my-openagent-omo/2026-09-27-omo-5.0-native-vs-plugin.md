# OMO 5.0：独立版（omo-ai）与插件版（oh-my-openagent）的区别

本机会话中调查 `ncu` 提示 `oh-my-openagent 4.19.4 → 5.0.0` 的破坏性升级，逐项取证。

## registry 一手事实（bin 与依赖）

对比 npm registry 上两版 `oh-my-openagent`：

| 包@版本 | bin 声明 |
|---|---|
| oh-my-openagent@4.19.4 | lazycodex、lazycodex-ai、oh-my-openagent、oh-my-opencode、omo |
| oh-my-openagent@5.0.0 | 同上但删除 omo，新增 omo-agent-toolkit |
| omo-ai@5.0.0（新包） | `{"omo": "bin/omo.js"}` |

- `omo-ai@5.0.0` 依赖只有两项：`@code-yeongyu/senpi@2026.9.26`、`@babel/parser@8.0.4`。
- `omo-ai@5.0.0` 的 dependencies / peerDependencies / optionalDependencies 均**不包含** `oh-my-openagent`。独立版不依赖插件版。
- `omo-ai@5.0.0` 的 `engines.node` 要求 `>= 24.0.0`。
- 依赖裁剪：oh-my-openagent 4.19.4 有 17 个依赖，5.0.0 有 16 个，减少的是 `@code-yeongyu/comment-checker`。
- 两个包的 npm `repository` 字段都指向 `code-yeongyu/oh-my-openagent`。

## 定位区别（v5.0.0 release notes / 迁移指南，文档声明）

- oh-my-openagent = 插件版：装进宿主（OpenCode，及 Codex 用的 LazyCodex 支线）跑，靠宿主插件接口工作。
- omo-ai = 独立版（官方称 OmO Native）：独立命令行程序，就是 `omo` 命令。引擎是 senpi（release notes 称其为 Pi 的 fork），OMO 功能作为 extension 直接加载其中。
- release notes 首行大写：「PLEASE REMOVE OPENCODE V1 FOR OMO, LAZYCODEX, IMMEDIATELY」；正文缓和：不必删任何东西，插件版和 LazyCodex 都还能跑，但从这版起进入 degraded support——新功能先落 Native，部分功能因宿主承载不了永远不来。
- OpenCode v2：官方称「答案在做，需要时间」，过渡期建议跑 Native。
- deep-low 默认模型改为 gpt-5.6-sol-fast（medium），fallback gpt-5.6-sol（medium）；该 lane 只在连了这两个模型之一时出现；只有 GPT-6 Sol 的账号需 pin `categories.deep-low.model`。
- Native 独有能力（release notes 声明，插件版无）：CodeMode（eval cell 内直接调用工具、parallel/pipeline/agent）、git-markdown memory + self block + Kibitzer（常驻第二 agent loop，碰未判断 memory 时唤醒，5 个只读工具，不能写 memory）、mass ulw（DAG + workpools + 重试恢复）、omowright 内置浏览器、subagent 走共享 daemon、文件监视一 worker 管一 host、后台进程随 session 结束。引擎 pin 到 senpi 2026.9.26。

## metis / momus 别名取消（v5.0.0 tag 文档，configuration.md:200 / omo-json.md:290）

- `agents.metis` / `agents.momus`、`subagent_type: "metis"|"momus"` 不再解析到 `plan-consultant` / `plan-reviewer`。
- 别名窗口在 5.0.0-beta.51 之后关闭。
- config key 那条静默生效，不报提示；被当成「名叫 metis/momus 的普通自定义 agent」。

## 作者自述性能数字（未独立验证，非事实）

冷启动 5.8s → 850ms；`omo --help` 28ms；Kibitzer 召回 308ms → 约 5ms/工具调用；同模型下 Native 每轮上下文约插件版 0.39x（GPT-5.5）/ 0.69x（Opus 4.8）；某次 GPT-6 Astra 会话 footer 报 97.5% prompt cache 命中。

## 本机现状（只读实测）

- `~/.bun/install/global/node_modules/oh-my-openagent/package.json` version = 5.0.0（ncu 已升级插件版）。
- 升级后、安装 omo-ai 前：`~/.bun/bin/omo` 是 4.19.4 遗留 symlink，指向 `.../oh-my-openagent/bin/oh-my-opencode.js`；`omo --version` 打印裸 `5.0.0`（跑的是插件版 CLI，非 Native）。bun 全局与 `npm ls -g` 均无 omo-ai。
- `~/.omo/omo.jsonc` 存在 `[opencode]` 块下的 `"metis":` 与 `"momus":` 两个 key。
- Node 版本 v24.21.0，满足 Native 的 >= 24.0.0。
- `~/.omo/migration-backup-2026-07-28T16-27-18-360Z-opencode-config/` 已存在（早于本会话的一次 opencode-config 迁移备份）。
